# 관리 화면

[README](../README.md) · [설치](quickstart.md) · [수동 배포](onboarding.md#manual-deployment)

수집 상태 확인, AI 연결 설정, 이벤트 대화 선택, 태블릿 조작을 관리 화면에서 할 수 있습니다. 사용하는 컴퓨터에 ADB나 scrcpy를 설치할 필요는 없습니다.

<a id="access"></a>
## 접속

신규 설치가 출력하는 localhost 주소(기본 `http://localhost:18789/admin/`)를 여세요. 원격 서버라면 [SSH 포워딩](quickstart.md#local-and-ssh-admin-access)을 유지하세요. 기존 설치는 비공개 HTTPS 등 설정된 주소를 유지합니다. [패스키](passkeys.md)를 한 번 등록한 뒤 **패스키로 로그인**을 사용하세요. 서버 호스트에 등록한 패스키는 localhost에서 작동하지 않으므로 출처를 유지해야 합니다. `kakaotalk-bridge admin`으로 설정된 주소를 열 수 있습니다.

관리 화면에 Tailscale이나 OpenAI 터널은 필요하지 않습니다. 선택적으로 공용 HTTPS의 같은 포트에서 `/admin/`, `/mcp`를 제공할 수 있습니다. 이 경우 프록시가 관리 경로를 차단하지 않으면 로그인 화면은 공개됩니다. 비공개 관리 출처와 공개 MCP를 분리할 수도 있습니다. 자주 쓸 관리 주소를 북마크하세요.

세션은 30분, **로그인 유지**를 선택하면 7일간 유효하며 컨테이너 재시작 후에도 유지됩니다. **태블릿 및 설정 → 관리 브라우저**에서 취소하거나 **패스키 및 복구**에서 백업 패스키를 추가하세요. **잠금**은 관리자 로그인만 종료하며 태블릿 카카오톡은 로그아웃하지 않습니다. 패스키를 모두 잃었다면 서버에서 `kakaotalk-bridge passkey-login --enroll`을 실행하세요. 패스키가 설정되지 않으면 조작 기능은 잠겨 있습니다.

<a id="first-login"></a>
## 첫 로그인

관리 화면 로그인 후 새 기기 준비와 수집 구성 요소 설치가 자동으로 진행됩니다. 카카오톡 설치를 감지하면 새로고침 없이 준비를 마치고 앱을 엽니다. 기존 기기 등록과 수집 승인은 유지합니다. 준비가 실패하면 오류와 **다시 시도**를 표시하고 자동 작업을 멈춥니다. 카카오톡 로그인과 휴대폰 확인은 항상 직접 해야 합니다.

수집을 승인하기 전까지 관리 화면은 **카카오톡 연결** 단계만 표시합니다. 태블릿 화면 옆에 지금 할 일과 필요한 버튼만 나오며 **설치 → 로그인 → 수집 시작** 순서로 자동으로 넘어갑니다. AI 연결은 별도의 선택 사항입니다.

1. 자동 준비가 끝나면 [Aurora에서 **Kakao Corp.의 카카오톡**을 설치](#install-kakaotalk-in-aurora)하세요. Bridge가 감지해 수집 구성 요소를 설치하고 카카오톡을 엽니다. 공식 APK 전체 세트를 가져올 수도 있습니다.
2. 태블릿 화면을 클릭·드래그로 조작하세요. 카카오톡이 보이지 않으면 **카카오톡 열기**를 누르세요.
3. 카카오톡 로그인 화면에서 **다른 기기와 함께 사용**을 선택하세요. 로그인 화면이 보이는 동안 단계 안내에 이 옵션의 선택 여부가 표시됩니다. 옵션이 없거나 주 기기 이전을 요구하면 중단하세요.
4. 태블릿 입력란을 누르고 단계 아래의 **텍스트 입력**으로 아이디와 비밀번호를 보내 로그인하세요. 로그인 후 대화 복원을 물으면 **대화 복원하지 않기**를 누르세요. 관리 화면이 태블릿을 자동으로 다시 확인해 로그인을 감지합니다. 마지막 확인 후 15초가 지나고 20초 동안 태블릿을 조작하지 않았을 때 확인하므로, 조작하지 않으면 약 15초마다 확인합니다. 바로 확인하려면 **다시 확인**을 누르세요.
5. 휴대폰에서 기존 카카오톡 로그인이 유지되는지 직접 확인하고 **휴대폰의 카카오톡 로그인이 유지되고 있습니다**를 체크한 뒤 **메시지 수집 시작**을 누르세요. 옵션 화면을 확인하지 않고 먼저 로그인했더라도 휴대폰 로그인이 유지되면 그대로 승인할 수 있습니다. 승인하면 평소 관리 화면(**내 Bridge**)으로 바뀝니다.

수집 시작은 직접 확인한 내용을 기록합니다. 프로그램이 카카오톡 로그인 동작을 제어하거나 휴대폰 로그아웃을 막지는 못합니다.

승인은 승인할 때 태블릿 카카오톡에 로그인되어 있던 계정에 묶입니다. 같은 계정으로 로그인되어 있는 동안 승인이 유지되며 카카오톡이 업데이트되어도 계속 수집합니다. 태블릿에서 확인한 계정이 승인한 계정과 다르거나 계정을 확인할 수 없을 때, Android 빌드가 바뀌었을 때, 휴대폰 로그아웃을 기록했을 때는 수집을 멈추고 사유와 함께 **카카오톡 연결** 단계로 돌아갑니다. 다시 승인하려면 휴대폰을 확인하고 **메시지 수집 시작**을 다시 누르세요.

계정 확인은 변경을 감지하는 용도이며 보안 경계가 아닙니다. 로그아웃이나 계정 전환 후 카카오톡이 남기는 정보는 실제 기기에서 아직 확인하지 않았습니다.

<a id="install-kakaotalk-in-aurora"></a>
### Aurora에서 카카오톡 설치

**카카오톡 연결** 단계가 태블릿 화면 옆에 지금 할 일을 표시합니다.

1. 자동 준비가 끝나면 태블릿에 Aurora가 열립니다. 시작 안내와 약관을 확인하고, 설치 방식을 물으면 **Session Installer**를 선택하세요. 앱 설치 권한은 Bridge가 미리 허용합니다. Aurora가 보이지 않으면 **스토어 열기**를 누르세요.
2. **익명(Anonymous)** 로그인을 선택하세요. 스토어 로그인이며 카카오톡 로그인은 이후에 진행합니다.
3. Bridge가 Aurora 로그인을 감지하면 **Kakao Corp.의 카카오톡** 페이지를 엽니다. 열리지 않으면 **카카오톡 페이지 열기**를 누르거나 태블릿 검색란을 누르고 화면 키보드로 **KakaoTalk**을 입력해 선택하세요. Bridge의 **텍스트 입력**은 수집 구성 요소 준비 후 사용할 수 있습니다.
4. **설치(Install)** 버튼을 누르고 Android 확인 창이 나타나면 승인하세요. 다운로드·설치 중에는 관리 화면을 열어 두세요.
5. Bridge가 구성 요소를 준비하고 카카오톡을 열 때까지 기다리세요. 단계가 **로그인**으로 바뀌면 [위 로그인 절차](#first-login)를 따르세요.

| 막힌 지점 | 다음 조치 |
| --- | --- |
| 익명 로그인·다운로드 실패 | 스토어 오류를 확인하고 다시 시도하세요. [Aurora 문제 해결](https://auroraoss.gitbook.io/wiki/troubleshooting-and-faqs/faqs/aurora-store)을 참고하세요. |
| Android가 설치 차단 | Android 설정에서 Aurora의 **이 출처 허용**을 켜고 **뒤로**로 돌아와 **설치**를 다시 누르세요. |
| 로그인·설치 후에도 단계가 바뀌지 않음 | 단계 안내의 **다시 확인**을 누르세요. 준비 오류가 표시되면 해결한 뒤 **다시 시도**를 누르세요. |

공식 APK 세트가 있다면 [APK 가져오기](#installation)를 사용할 수 있습니다. Aurora 문구는 버전·언어에 따라 달라질 수 있습니다. 설치할 앱이 Kakao Corp.의 카카오톡인지 확인하세요.

<a id="installation"></a>
## 설치와 복구

기본 경로는 자동 준비입니다. 복구용 **태블릿과 Aurora 준비**, **수집 구성 요소 설치…**는 **태블릿 및 설정 → 설치**에 있습니다. 설정 중에는 단계 안내 아래의 **설치**를 여세요. `kakaotalk-bridge import-apks /path/to/folder`로 APK를 가져올 수도 있습니다.

처음 등록하기 전에 카카오톡 서명을 확인합니다. 이미 등록된 태블릿과 기존 수집 승인은 유지합니다. CLI의 `bootstrap`은 잠긴 새 등록을 만들어 승인을 초기화하므로 일상적인 복구에 사용하지 마세요.

<a id="everyday-use"></a>
## 평소 사용

**내 Bridge** 현황에는 서로 다른 세 가지 상태가 표시됩니다.

| 항목 | 의미 |
| --- | --- |
| 메시지 수집 | 수집 상태와 마지막 관측 시각. 일부 기록만 수집하며 휴대폰 전체 기록을 보장하지 않음 |
| 원격 AI 사용 기록 | 승인된 OAuth·터널 연결의 마지막 도구 호출 성공 또는 첫 호출 대기. 태블릿 카카오톡이 아직 알림을 표시한 적 없으면 **메시지 전송 준비 필요**도 표시 |
| 내 휴대폰 | 마지막 직접 확인 기록. 24시간 후 **재확인 필요**는 알림이며 로그아웃 감지가 아님 |

수집이 승인되면 **태블릿 및 설정**은 접혀 시작합니다. 메뉴로 **AI 연결**, **대화 이벤트**, **태블릿 및 설정**을 바로 열 수 있습니다. 승인 전(처음 설정, 승인 취소 후)에는 **카카오톡 연결** 단계와 태블릿만 펼쳐 표시합니다.

태블릿과 설정은 넓은 화면에서 나란히, 작은 화면에서는 세로로 배치됩니다. 해당 영역이 열려 있고 페이지가 보일 때 약 1.2초마다 화면을 갱신합니다. 영역을 닫으면 화면 조회만 멈추며 메시지 수집은 계속됩니다. 클릭·드래그·Android 버튼으로 조작하세요.

**텍스트 입력**은 선택된 입력란에 값을 넣고 웹 입력란을 비웁니다. 기본적으로 내용을 가립니다. Enter나 기기 버튼을 누르기 전에는 자동 제출하지 않습니다. 대화방을 직접 열면 카카오톡 읽음 상태가 바뀔 수 있습니다.

**일시 정지**는 화면 갱신과 화면 클릭을 멈춥니다. 메시지 수집과 Android 버튼은 계속 사용할 수 있습니다.

<a id="reading-status"></a>
## 상태 읽기

**상태 확인**은 현재 화면과 저장된 확인 기록을 가져옵니다. 기기를 조작하거나 60초가 지나면 화면 점검이 오래된 것으로 표시됩니다. **점검 결과 갱신 필요**, **승인됨 · 마지막 점검 기준**은 시간이 지났다는 뜻이며 승인을 취소했다는 뜻이 아닙니다. 현재 태블릿 상태가 필요한 작업에는 새 점검이 필요합니다.

| 항목 | 의미 |
| --- | --- |
| 태블릿 | 연결 상태와 태블릿 카카오톡의 로그인 여부. 로그인되지 않았으면 현재 화면(로그인 화면 등) |
| 휴대폰 | 사용자가 직접 확인하거나 로그아웃을 신고한 시각 |
| 수집 승인 | 승인한 카카오톡 계정과 Android 빌드가 현재 태블릿과 일치하고 휴대폰 로그아웃이 기록되지 않았는지 여부. 아니면 사유 표시 |
| 메시지 수집 중 | 최근 Iris DB 접근과 수집 승인이 유효함. 전체 기록 복원을 뜻하지 않음 |

휴대폰 로그인은 자동 감시하지 않습니다. **휴대폰 확인 기록 보기**를 누르고 휴대폰 카카오톡을 확인한 뒤 체크하고 **확인 시간 갱신**을 누르세요. 비활성화되면 버튼 아래 설명을 읽고 필요하면 **태블릿 점검 새로고침**을 누르세요. 24시간 이상 지난 기록에는 재확인 안내가 붙습니다.

휴대폰에서 로그아웃되었다면 **로그아웃됨 · 수집 중지**를 누르세요. 수집 승인을 취소합니다. 관리 화면이 **카카오톡 연결** 단계로 돌아갑니다. 다시 시작하려면 두 기기의 로그인을 확인하고 **메시지 수집 시작**을 다시 누르세요.

<a id="ai-connections"></a>
## AI 연결

1. **AI 연결 → AI 연결 설정**을 여세요. **사용할 곳 → 서버 준비 → AI 앱에 추가** 중 지금 단계 하나만 표시합니다.
2. **어디에서 메시지를 사용하시겠어요?** 화면에서 **ChatGPT**, **내 컴퓨터의 AI 앱**, **다른 원격 AI 서비스** 중 하나를 고르세요. 나중에 하려면 **닫기**를 누르세요. 수집은 계속됩니다.
3. **서버 준비**에서 방식을 확인하고 필요한 값을 입력하세요. ChatGPT는 **개인 터널**(권장)·**기존 HTTPS 주소**·**Tailscale로 주소 만들기**, 원격 서비스는 HTTPS·Tailscale 중 고를 수 있습니다. 내 컴퓨터의 AI 앱(stdio)은 이 단계 없이 바로 마지막 단계로 갑니다. 여러 방식을 함께 사용할 수 있고 기존 연결은 유지됩니다.
4. 설정이 끝나면 **AI 앱에 추가** 단계에 터널 ID·MCP URL·stdio 설정과 따라 할 순서가 나옵니다. [AI 클라이언트에서 마무리](#finish-in-your-ai-client)하세요. HTTPS는 OAuth를, 개인 터널은 승인된 비공개 연결을 사용합니다.
5. AI에 수집 상태를 요청하고 휴대폰에서 직접 보낸 메시지를 조회하세요. 원격 연결은 요청이 성공하면 마지막 단계에 성공 시각이 표시됩니다.

HTTPS에는 `https://bridge.example.com` 또는 전체 `https://bridge.example.com/mcp` 주소를 입력할 수 있습니다. 다른 경로·쿼리·내장 인증 정보는 거부합니다. 프록시는 미리 연결되어 있어야 하며 외부 DNS나 프록시를 이 폼에서 설정하지는 않습니다.

터널에는 ID, 실행용 키, 명시적 접근 승인이 필요합니다. 같은 ID에는 저장된 키를 재사용할 수 있고 브라우저에 키를 다시 반환하지 않습니다. Tailscale은 설치·공개 동의가 필요합니다. 제공업체 링크가 표시되면 승인하고 **설정 계속**을 누르세요. CLI와 서비스 요구 사항은 [고급 설치](onboarding.md#connect-an-ai-client-optional)를 참고하세요.

<a id="finish-in-your-ai-client"></a>
### AI 클라이언트에서 마무리

AI 클라이언트 옆에 관리 화면을 열어 두세요. **AI 앱에 추가** 단계가 표시되면 그 안내에 따라 클라이언트도 설정해야 합니다.

ChatGPT 웹의 [플러그인](https://chatgpt.com/plugins)에서 **+ → 사용자 지정 MCP 서버 만들기(Create custom MCP server)** 메뉴를 열고 이름을 **KakaoTalk Bridge**로 지정하세요.

| Bridge 연결 방식 | 클라이언트 입력 | 접근 완료 |
| --- | --- | --- |
| 개인 터널 | **터널(Tunnel)**, 저장된 터널 ID, 승인된 개인 연결의 **인증 없음(No authentication)** | Bridge에서 접근이 허용되어야 합니다. 터널이 없으면 워크스페이스 연결과 Tunnels Read + Use 권한을 확인하세요. [터널 준비](openai-tunnel.md#before-setup) |
| 기존 HTTPS·Tailscale | `/mcp`를 포함한 **MCP 서버 URL**, **OAuth**. ChatGPT가 등록 방식을 물으면 CIMD, 선택적 고정 인증 정보는 비워 둠 | 패스키로 동의하거나 **AI 연결 → 연결 승인**에서 코드를 맞춘 뒤 클라이언트로 돌아가 완료 |
| 로컬·SSH 앱 | **설정 복사** 후 기존 서버를 유지하며 `mcpServers`에 `kakaotalk` 추가. 폼이라면 명령·인수 복사 | 저장 후 MCP 새로고침 또는 앱 재시작, Bridge 활성화. SSH는 비밀번호 입력 없이 접속 가능해야 함. [예시](api.md#stdio-mcp) |

ChatGPT에서 안내를 확인하고 플러그인을 만들어 설치한 뒤 대화에서 **@KakaoTalk Bridge**를 선택하세요. 생성할 수 없으면 워크스페이스 권한과 [공식 안내](https://developers.openai.com/api/docs/guides/custom-mcp-server)를 확인하세요.

**Tailscale 승인 요청:** 표시된 링크에서 로그인·승인을 완료하고 돌아와 **설정 계속**을 누르세요. 추가 요청이 있으면 반복하세요. MCP URL이 저장되면 HTTPS 절차를 따르세요.

**내 메시지로 확인:** AI에 수집 상태를 요청하세요. 수집 시작 후 휴대폰에서 ‘Bridge 확인 14:32’ 같은 구별되는 메시지를 나에게 보내고 정확한 문구를 찾아 달라고 하세요. 본문과 시각을 확인하세요. 원격 연결의 성공 요청은 **원격 AI 사용 기록**에 표시하며 로컬 stdio는 기록하지 않습니다. OAuth 요청이 만료되면 새로 연결하고 새 코드를 승인하세요.

<a id="progress-and-recovery"></a>
### 진행 상황과 재시도

연결 설정은 한 번에 하나씩 진행합니다. 브라우저를 닫아도 작업은 계속되며, 다시 열면 진행 상황을 확인할 수 있습니다. 설정 서비스가 재시작되어 작업이 중단되면 화면 안내에 따라 다시 시도하세요.

실패하면 **서버 준비** 단계에 원인이 표시됩니다. 값을 고친 뒤 **다시 시도**를 누르세요. 폼에서 지워진 실행용 키가 저장되지 않았다면 다시 입력해야 합니다. 작업이 진행 중이거나 Tailscale 승인을 기다리는 동안에는 그 방식의 단계를 계속 표시합니다. 서버 점검은 마지막 단계의 **서버 연결 확인**으로 다시 실행합니다. 선택한 방식은 성공 후 저장하며 점검·실패로 덮어쓰지 않습니다. 저장하지 않은 편집 내용은 새로고침 후 유지되지 않을 수 있습니다.

HTTPS·터널 안내는 현재 설정에서 가져오므로 점검·실패·새로고침 후에도 유지됩니다. 터널 카드의 **연결 안내**로 바로 열 수 있습니다. 저장된 설정도 별도 승인이나 복구가 필요할 수 있습니다.

<a id="what-each-status-proves"></a>
### 각 상태의 의미

| 표시 | 확인된 내용 |
| --- | --- |
| **AI 앱에 추가** 단계·서버 확인 통과 | 서버 설정이나 점검 완료. AI 클라이언트 연결 완료는 아님 |
| 접근 허용됨 | OAuth 클라이언트·개인 터널에 접근 권한을 부여함. 실제 사용 여부는 호출 기록에서 확인 |
| 첫 AI 요청 대기 중 | 승인되었지만 성공한 도구 호출 기록이 없음 |
| 도구 호출 성공 기록 있음 | 표시된 시각에 원격 MCP 도구가 완료됨. 현재 연결 가능 여부는 별도 확인 필요 |

도구 목록 조회와 실패한 호출은 활동을 갱신하지 않습니다. 기록은 이 기능이 포함된 버전부터 시작하며 이전 호출은 소급하지 않습니다. 로컬 stdio도 제외합니다. **서버 연결 확인**은 서비스를 별도로 점검합니다. **연결 새로고침**은 승인·활동을 다시 가져오며 AI를 호출하지 않습니다.

OAuth는 관리·공개 MCP가 같은 HTTPS 패스키 호스트라면 연결 브라우저에서 동의합니다. localhost·비공개 관리 호스트가 별도라면 **AI 연결**에서 코드를 맞추세요. CLI로 설정한 개인 터널은 **개인 터널 허용**으로 승인합니다. 카드에서 언제든 연결을 해제할 수 있으며 관리 화면 잠금과는 별개입니다.

<a id="conversation-events"></a>
## 대화 이벤트

켜 둔 대화에 새 카카오톡 메시지가 오면 연결된 AI에 바로 알리는 선택 기능입니다. 대화를 검색하고 **꺼짐**에서 **허용**으로 바꾸세요. **허용됨 · 아직 AI 구독이 없습니다**라면 AI에도 구독을 요청하세요. 구독 후 실제 알림이 오는지도 확인하세요. 같은 이름의 대화는 **대화 식별자**로 구분하세요.

모든 대화는 기본적으로 꺼져 있습니다. 끄면 대기 전송을 취소하고 대기 조회에서 제외하지만 수집·일반 검색은 계속됩니다. 갱신과 전달 제한은 [MCP 이벤트](events.md)를 참고하세요.

<a id="troubleshooting"></a>
## 문제 해결

| 상황 | 조치 |
| --- | --- |
| 연결 대기 중 | 서버에서 redroid 시작을 확인하고 새로고침 |
| 텍스트가 입력되지 않음 | 키보드를 연결하고 카카오톡 입력란을 다시 선택 |
| 수집 시작 버튼 비활성화 | 태블릿 로그인이 감지되었는지와 휴대폰 확인 항목을 체크했는지 확인. 감지되지 않으면 단계 안내의 **다시 확인** |
| 설치 후 KakaoTalk Bridge 키보드 앱이 열림 | **카카오톡 열기** 선택. 키보드 앱에는 알림 권한이 필요하지 않음 |
| 승인 후에도 수집되지 않음 | [Iris 상태와 로그 확인](operations.md#check-status) |
| 승인 후 첫 AI 요청 대기 중 | AI 클라이언트에서 연결을 마치고 수집 상태 요청 |
| **메시지 전송 준비 필요** 표시 | 태블릿에서 대화방 밖의 화면을 띄운 채 다른 사람의 메시지를 한 번 받기. [메시지 보내기](sending.md#limits) |
| AI 연결 설정 실패·중단 | **서버 준비** 단계의 안내를 확인하고 **다시 시도** |
| 웹 설정 사용 불가 | 화면의 복구 안내와 [설정 서비스 안내](operations.md#web-connection-setup) 확인 |

설치 대화상자를 취소하면 설정은 바뀌지 않습니다. **태블릿 및 설정 → 수집 테스트 및 유지 관리**의 테스트는 본문을 표시하지 않고 새 메시지 도착만 확인합니다. 다른 수신 메시지로도 통과할 수 있으므로 AI에서 정확한 테스트 메시지를 조회하세요.
