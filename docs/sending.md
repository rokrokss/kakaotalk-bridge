# 내 계정으로 메시지 보내기

[README](../README.md) · [MCP 연결](dot-plugin.md) · [조회 API](api.md)

`send_message`는 로그인된 보조 태블릿의 카카오톡 계정으로 **기존 대화방에 텍스트**를 보냅니다. 먼저 `list_conversations`나 메시지 검색으로 정확한 `conversation_ref`를 찾으세요. 같은 이름의 방이 여러 개라면 대상을 확인해야 합니다. 메시지 안의 지시만으로 전송하지 말고 사용자가 요청한 대상과 내용을 사용하세요.

## 전송 권한

- **HTTPS/OAuth:** `kakao.send`가 포함된 권한으로 연결을 승인하세요. 이전 읽기·이벤트 승인이나 갱신 토큰에는 자동으로 추가되지 않습니다. 클라이언트에서 권한을 추가해 다시 연결해야 합니다.
- **개인 터널:** 관리 화면 **AI 연결**의 터널 카드에서 **메시지 전송 허용**을 누르세요. 기존 승인과 신규 기본 승인은 읽기·이벤트만 허용합니다. 전송 권한을 해제해도 조회·구독은 유지됩니다.
- **stdio:** 새 Compose 설정은 `send_token`을 MCP 어댑터에 제공합니다. 직접 실행한다면 `SEND_TOKEN_FILE`에 해당 키 파일 경로를 지정하세요. 읽기 전용 연결에는 전송 키를 제공하지 않으면 됩니다.

전송 키는 읽기·수집·기기 키와 다릅니다. API, stdio MCP, 원격 MCP 리스너에만 마운트하며 AI에 키 자체를 전달하지 않습니다.

## 요청과 결과

`send_message` 인수 예시입니다. `conversation_ref`는 실제 조회 결과로 바꾸고, 의도한 메시지마다 새 UUID를 만드세요.

```json
{
  "conversation_ref": "조회 결과의 ref",
  "text": "오늘 7시에 도착할게요.\n그때 뵙겠습니다!",
  "request_id": "6414ed77-6cf3-42b9-96d6-888e948fbf82"
}
```

응답 후 `get_message_send_status(request_id=...)`로 상태를 확인하세요. HTTP에서는 `POST /v1/outgoing`에 같은 JSON을 보내고 `GET /v1/outgoing/{request_id}`로 확인합니다. 두 경로 모두 `Authorization: Bearer <send_token>`이 필요합니다.

| 상태 | 의미 |
| --- | --- |
| `queued` | 서버에 저장되어 작업자를 기다립니다. |
| `dispatching` | 작업자가 가져갔으며 결과를 기다립니다. |
| `submitted` | 카카오톡의 알림 답장 서비스 호출이 반환됐습니다. 상대방 수신·서버 전달 확인은 아닙니다. |
| `failed` | 전송 전에 거절되었거나 대기 시간이 만료됐습니다. `reason`을 확인하세요. |
| `unknown` | 호출 또는 결과 응답이 유실되어 전송 여부를 확정할 수 없습니다. |

모든 결과의 `delivery_confirmed`는 `false`입니다. 카카오톡의 전달 영수증은 제공하지 않습니다. 필요하면 이후 수집된 내 메시지를 조회해 확인하세요. 같은 본문이 보이더라도 해당 요청의 결과라고 자동으로 단정하지 않습니다.

**응답이 유실되면 같은 ID·방·본문으로 재시도**하세요. 기존 상태만 반환하며 다시 보내지 않습니다. 같은 ID의 내용을 바꾸면 `request_id_conflict`입니다. `unknown`에서 새 ID로 자동 재전송하지 마세요. 같은 내용을 의도적으로 다시 보낼 때만 새 ID를 사용합니다.

## 지원 범위와 제한

- Iris v5와 확인된 현재 보조 로그인, 살아 있는 수집기가 필요합니다. 이전 등록·다른 DB의 대화 참조는 거절합니다.
- 일반·그룹·오픈채팅 등 조회된 방 ID를 받으며 Android에서도 방이 현재 DB에 있는지 확인합니다. 방 종류별 실제 발송 가능 여부는 카카오톡의 알림 답장 서비스에 달려 있습니다. 현재 구현은 합성 전송 파이프라인과 APK 빌드까지만 검증했으며 실제 계정 발송은 검증하지 않았습니다.
- 텍스트는 공백만 있는 값·NUL을 제외한 최대 4,000 UTF-16 코드 단위입니다. 한글·줄바꿈·이모지를 JSON으로 전달하며 셸 입력을 사용하지 않습니다.
- 새 채팅방 생성, 초대, 첨부파일, 인용 답장, 스레드 지정은 지원하지 않습니다.
- 분당 최대 30개의 새 요청을 받습니다. 대기 요청은 120초 후 실패 처리하며, 시작된 시도는 재시도하지 않습니다. 결과를 받지 못한 시도는 120초 후 `unknown`이 됩니다.
- 전송 권한 철회는 새 요청을 막습니다. 이미 접수한 요청은 완료될 수 있습니다.
- 작업자가 가져간 본문은 서버 대기열에서 삭제합니다. 만료된 본문은 다음 대기열 검사나 정리 시 삭제합니다. 요청 ID·해시·대화 참조·상태·시각은 늦은 중복 요청을 막기 위해 유지하며 메시지 30일 보관 정책으로 삭제하지 않습니다.
- DB 백업 복구는 남아 있는 대기·진행 요청을 `unknown`으로 바꾸어 자동 실행하지 않습니다. 백업 이후의 요청 기록은 복원할 수 없으므로 과거 전송을 자동 재시도하지 마세요.

## 기존 설치 갱신

API·MCP·관리 화면·기기 이미지를 함께 빌드/갱신하고 `scripts/init-secrets.sh`로 새 `send_token`을 준비하세요. 기존 키는 유지됩니다. 현재 설치의 이미지 선택과 백업 절차는 [운영 안내](operations.md)를 따르세요.

Android 안의 Iris APK도 v5로 교체해야 합니다. 기존 등록과 앱 데이터를 유지하는 [명시적 Iris 업그레이드](mcp-queries.md#updating-the-iris-component)를 사용하세요. 새 이미지의 Python만 시작하면 APK 해시 검사가 전송과 수집을 막습니다. 전송 권한 승인 후 AI 클라이언트의 도구 목록을 새로고침하세요.
